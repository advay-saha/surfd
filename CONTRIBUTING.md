# Contributing to surfd

Thanks for helping. surfd aims to stay small, so the best contributions make
something simpler, more reliable or easier to understand.

## Getting set up

Any Linux machine works for the code; Fedora is needed for RPMs and ISOs.

```sh
# Fedora
sudo dnf install sway foot fuzzel waybar mako python3-pytest python3-tomlkit python3-gobject \
  gtk4 libadwaita ShellCheck ruff pykickstart desktop-file-utils appstream librsvg2-tools python3-pillow
# Debian/Ubuntu (for development only)
sudo apt install sway foot fuzzel waybar mako-notifier python3-pytest python3-tomlkit python3-gi \
  gir1.2-gtk-4.0 gir1.2-adw-1 shellcheck desktop-file-utils appstream librsvg2-bin python3-pil
pipx install ruff pykickstart
```

```sh
make check        # lint + all tests (what CI runs)
make art          # regenerate artwork into build/art
make screenshots  # run the real session headless and capture screenshots
```

## Ground rules

- **One source of truth.** Settings live in `src/surfctl/surfd/schema.py`;
  the settings reference doc, CLI help and GUI read from it. After changing it
  run `make docs`.
- **Never break the session.** Generators must produce config that passes
  `sway --validate`. Add a test in `src/surfctl/tests/` for every new setting
  and generator branch.
- **Package lists live in the kickstarts.** After editing `%packages`, run
  `make container-packages` and, on Fedora, `./build.sh check`.
- **Lightweight by default.** A new default package needs a reason in the PR
  (what it does, installed size, RAM if it runs at login).
- **Original artwork only.** No third-party logos, photos or icons. Art is
  generated by `theme/tools/make_art.py` or added as SVG under CC BY-SA 4.0.
- **No Fedora trademarks** in surfd's own files, apart from the factual
  "based on Fedora Linux, not an official Fedora project".

## Adding a theme

See [docs/theme-making.md](docs/theme-making.md). New built-in themes must pass
the WCAG contrast test in `src/surfctl/tests/test_keys_themes.py`.

## Commits and pull requests

- Small, focused PRs; describe what you tested (VM, hardware model, test run).
- Shell: `shellcheck` clean. Python: `ruff check` clean, type hints welcome.
- Hardware reports: include `surfd-hwprobe --json` output.

## Releasing

1. Bump `VERSION`, the `Version:` in each spec and `__version__` in
   `src/surfctl/surfd/__init__.py`; add `%changelog` entries.
2. `make check`, then on Fedora `./build.sh rpms && ./build.sh check`.
3. Boot-test the ISO (docs/testing.md).
4. `git tag v0.x.y && git push --tags`; GitHub Actions builds and publishes
   both ISOs with SHA256 checksums.
